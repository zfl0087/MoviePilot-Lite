# MoviePilot Lite 兼容性

## 1. 文档目的

本文档定义 MoviePilot Lite 对配置、数据库、认证、API、网盘、插件、消息渠道、媒体服务器、前端和部署环境的兼容承诺。

本文档中的“支持”是需要测试证据和版本记录的合同，不等同于源码仍然存在。未经测试的对象不得仅凭推测标记为支持。

产品范围以根目录 `PROJECT_BRIEF.md` 为准，技术边界以 `docs/ARCHITECTURE.md` 为准，上游版本配对和发布证据以 `docs/UPSTREAM_SYNC.md` 为准。

## 2. 当前状态

当前项目仍未形成可验收的 Lite 运行版本。固定能力配置、API 导入前门控和 PT 用户认证运行链路已经有自动化测试证据；模块发现、消息命令、依赖、Docker、前端及真实 115 Canary 仍未完成。因此本文档同时记录已实现边界和后续目标，不代表完整兼容认证。

首个实现基线：

| 组件 | 官方版本或分支 | 基线提交 |
|---|---|---|
| MoviePilot 后端 | `v2.14.5` / `v2` | `8b5524a321c940f337873cefa54ba6a58462f9a4` |
| MoviePilot 前端 | `v2.14.5` / `v2` | `435e9ecfdd4febf791fd581b3be9233816cebf7f` |

每个正式 Lite 版本发布时，必须把本节更新为该版本实际测试过的完整版本矩阵。

## 3. 兼容等级

| 等级 | 含义 | 发布要求 |
|---|---|---|
| 支持 | 纳入版本测试和 Canary 验收 | 必须有自动化或真实验收证据 |
| 有条件支持 | 只在指定版本、配置或部署方式下支持 | 必须记录适用条件和限制 |
| 保留数据 | 功能不运行，但数据和配置保留用于回退 | 必须验证不会主动删除或改写 |
| 未验证 | 尚未形成可用性承诺 | 启用前需要兼容检查，不得宣传为支持 |
| 不支持 | 明确移除或超出项目范围 | 不得导入、注册、运行或提供空壳入口 |

兼容等级适用于明确版本。插件、前端或后端升级后，原等级不能自动继承。

## 4. 配置兼容

| 配置或环境 | 目标等级 | 规则 |
|---|---|---|
| 官方 `/config` 目录 | 支持 | 首次 Lite 启动前必须备份 |
| SQLite | 支持 | 唯一正式支持的数据库 |
| `API_TOKEN` | 支持 | 保持官方名称、用途和认证方式 |
| Lite 能力配置版本 2 | 支持 | `auxiliary-auth` 已归入禁用集合；前端配对后必须使用相同版本 |
| `U115_APP_ID` | 支持 | 保持官方配置名称 |
| `U115_AUTH_SERVER` | 支持 | 保持可配置，不写死服务地址 |
| 已有插件配置和数据 | 保留数据 | 按插件兼容等级决定是否加载 |
| PT、下载器和订阅配置 | 保留数据 | 不执行、不显示为可用能力 |
| `AUTH_SITE` | 不支持 | 已从有效配置模型移除；旧环境输入被忽略，历史数据库/未知配置数据不主动删除 |
| PostgreSQL | 不支持 | 不提供自动迁移，不得静默创建空 SQLite 替代 |
| Redis | 不支持 | 不连接、不迁移缓存数据 |
| CookieCloud | 不支持 | 不保留接口或后台同步链路 |

检测到 PostgreSQL 配置时，Lite 必须停止启动并明确提示迁移要求。禁止在用户不知情的情况下切换到新建 SQLite 数据库，以免表现为数据丢失。

已移除配置默认只保留原始数据，不主动清理。将来回退官方版本时，应由对应官方版本继续解释这些配置。

## 5. 身份认证兼容

### 5.1 支持

- 单管理员账号和密码登录。
- 登录会话和 Token 安全。
- `API_TOKEN` 认证。
- 官方 FastAPI 身份依赖和管理员权限检查。

本地管理员登录、`API_TOKEN` 管理员上下文和资源 Token 当前固定使用等级 `1`；该等级只表达 Lite 本地权限上下文，不依赖任何 PT 站点在线状态。

### 5.2 不支持

- PT 站点用户认证。
- `AUTH_SITE` 及其在线验证链路。
- 用户注册和多用户管理。
- 角色系统和 SSO。
- MFA、Passkey 等辅助认证入口（`auxiliary-auth`）。

### 5.3 插件认证级别

MoviePilot 官方插件级别含义继续用于判断插件是否依赖已移除认证能力：

| 插件级别 | Lite 处理 |
|---|---|
| `level 1` | 可进入兼容检查，不依赖 PT 站点认证 |
| `level 2` | 不支持，依赖站点认证 |
| `level 3` | 不支持，依赖站点和密钥认证 |
| `level 99` | 不支持，依赖站点和特殊密钥认证 |

Lite 不伪造、不提高官方认证级别，也不使用固定成功结果模拟在线认证。级别 `1` 只代表插件可以进入后续能力和版本检查，不代表插件已经兼容 Lite。

当前实现还接受未声明等级和显式 `level 0` 的插件进入后续检查；`level 2`、`3`、`99` 均直接拒绝，不读取站点认证状态，也不使用 `PLUGIN_*_PRIVATE_KEY` 提升权限。

## 6. REST API 兼容

保留 API 应尽量与相同官方版本保持路径、请求参数、身份认证、响应模型和错误语义一致。

### 6.1 目标支持接口

- 本地管理员登录、会话和必要账户设置。
- 网盘、文件浏览和文件管理。
- 元数据识别、预览和人工纠正。
- 文件整理、整理历史和失败重试。
- 插件市场、安装、升级、配置和插件动态 API。
- 消息渠道、通知和必要回调。
- Emby、Jellyfin 和 Plex。
- 必要系统设置、日志和运行状态。

### 6.2 不支持接口

- PT 站点、索引器和站点认证。
- 下载器、种子和下载任务。
- 影视订阅。
- 资源搜索、推荐、探索、榜单和人物发现。
- Agent、LLM、MCP、OpenAI 和 Anthropic。
- 工作流编辑和执行。
- Radarr、Sonarr 兼容接口。
- CookieCloud 接口。

不支持的 API 不注册路由，访问时预期得到标准未找到响应。禁止保留返回空数据或虚假成功的兼容空壳。

能力配置版本 2 已在正常 FastAPI 初始化路径完成主 API、Radarr/Sonarr 和 CookieCloud 的导入前门控。启动路径不再执行 PT 用户认证及认证失败通知，Scheduler 不再注册 `cookiecloud`、`user_auth`、`sitedata_refresh`，通用数据清理也不再删除历史 `siteuserdata`。保留端点内部的其他历史业务耦合、剩余后台服务与任务、消息命令、依赖和前端页面仍须通过后续独立变更继续裁剪。

插件动态 API 只有在插件本身通过兼容检查并成功加载后才可注册。

## 7. 数据库兼容

| 迁移方向 | 目标等级 | 条件 |
|---|---|---|
| 相同官方基线 SQLite → Lite | 支持 | 启动前完成备份和迁移验证 |
| Lite → 对应官方基线 | 支持目标 | 必须通过实际回退测试 |
| 官方较新版本 → 较旧 Lite | 不支持 | 不承诺跨版本数据库降级 |
| PostgreSQL → Lite | 不支持 | 不提供自动转换 |
| Lite SQLite → PostgreSQL | 不支持 | 超出 Lite 范围 |

数据规则：

- 不主动删除已移除功能的表、字段、配置或历史记录。
- 原则上保留官方 Alembic 迁移，即使迁移涉及 Lite 不运行的能力。
- Lite 专属数据库迁移必须保持最少，并记录官方回退影响。
- 未知字段和未知配置默认保留。
- Redis 只属于缓存，不作为需要迁移的数据源。
- 升级和回退测试必须使用副本，不能直接操作真实生产数据库。

## 8. 网盘与存储兼容

| 对象 | 目标等级 | 范围 |
|---|---|---|
| 官方115网盘适配器 | 支持 | 授权、浏览、整理、STRM 和异常重试 |
| 官方其他存储适配器 | 有条件支持 | 保留源码，按配置延迟加载，首版不进行全部真实账号验收 |
| 未配置存储适配器 | 不加载 | 不导入、不实例化、不创建后台任务 |
| 第三方存储插件 | 未验证 | 逐插件、逐版本检查 |

保留官方适配器源码只代表继续维护上游合并能力，不代表所有适配器都已经通过真实账号验收。

115 是首个正式版本的真实验收对象，至少覆盖：

- OAuth 或官方 API 授权。
- 文件和目录访问。
- 分享链接转存。
- 元数据识别和文件整理。
- STRM 更新。
- 消息通知。
- 媒体服务器刷新。
- 异常重试、重启恢复和升级回退。

## 9. P115StrmHelper 兼容合同

P115StrmHelper（115网盘STRM助手）是目标115工作流的必装插件，但由用户手动安装。

公开来源：

- [DDSRem-Dev/MoviePilot-Plugins](https://github.com/DDSRem-Dev/MoviePilot-Plugins)
- [P115StrmHelper 文档](https://github.com/DDSRem-Dev/MoviePilot-Plugins/tree/main/docs/p115strmhelper)

### 9.1 安装和更新

- Lite 不预装、不自动安装、不在后台自动下载插件。
- 插件缺失时 Lite 正常启动。
- 插件缺失、未启用或不兼容时，115分享转存及相关 STRM 入口必须显示明确原因。
- 每个 Lite 版本必须记录一个已经验证的插件版本或明确版本范围。
- 不自动追随插件最新版，更新前先在 Canary 验证。
- 插件版本、依赖或 MoviePilot 最低版本要求变化后，重新进行兼容认证。

### 9.2 支持范围

Lite 只承诺经过测试的以下插件能力：

- 115分享链接转存。
- 115文件整理。
- STRM 全量、增量或整理事件生成中被明确启用的部分。
- 与 Lite 消息通知和媒体服务器刷新相关的部分。
- 首个版本验收明确列出的异常恢复流程。

以下插件内部能力不自动进入 Lite 支持范围：

- PT、资源搜索和订阅。
- 下载器和离线下载链路。
- Agent、LLM 和 MCP。
- HDHive、浏览器内核和反爬链路。
- 依赖 Redis、CookieCloud 或 `ffmpeg` 的功能。
- 任何未列入 Lite 能力配置的扩展服务。

插件某一非目标功能不可用，不等于整个插件必然不兼容；但如果该功能的依赖在插件导入阶段被强制加载，导致插件无法启动，则该插件版本不能标记为支持。

### 9.3 隐私和遥测

P115StrmHelper 文档声明包含可选 Sentry 分析组件。Lite 支持配置必须关闭非必要错误上报和环境信息上传。

- 可选遥测关闭后插件仍须正常完成目标工作流。
- 如果某版本无法关闭非必要遥测，该版本不得标记为 Lite 支持版本。
- Lite 核心不得替第三方插件承诺隐私行为；每次版本验收必须重新检查插件配置和网络请求。

### 9.4 当前状态

在首个 Lite 可运行版本和真实 Canary 验证完成前，P115StrmHelper 的状态是“必选验收对象，尚未认证”，不是已经支持。

## 10. 其他插件兼容

### 10.1 启用规则

- 依赖已移除能力的插件必须阻止启用，并显示具体缺失能力。
- 未知插件可以在市场中查看或由用户手动安装，但启用前必须通过静态能力检查。
- 未经测试的插件保持“未验证”状态。
- 不得为了兼容单个插件恢复完整 PT、下载器、订阅、Agent、Redis 或工作流核心。
- 插件的可选功能应按能力拆分；任何必须在导入阶段加载的不兼容依赖都会影响整个插件等级。

### 10.2 插件矩阵记录

每个经过验证的插件至少记录：

- 插件标识和名称。
- 插件来源仓库。
- 插件版本或版本范围。
- 最低和最高已测试 Lite 版本。
- 所需能力。
- 禁用的插件子功能。
- 测试结果和 Canary 日期。
- 已知风险和回退方法。

## 11. 消息与通知兼容

- 保留官方消息渠道身份、白名单、管理员白名单、用户绑定、命令权限和默认允许或拒绝行为。
- 不新增全局权限捷径，也不因 Lite 只有一个管理员就绕过渠道权限。
- 保留通知发送、必要回调和插件消息动作。
- 保留消息渠道接收115分享链接并转存的入口。
- PT搜索、下载、订阅和 Agent 命令不支持。
- 已移除动作不得保留返回虚假成功的命令分支。

各消息渠道只有在对应官方模块、依赖和实际配置通过测试后，才可标记为支持。未配置渠道必须延迟加载。

## 12. 元数据和文件整理兼容

目标支持：

- TMDB、豆瓣、Bangumi、TheTVDB 和 Fanart 等保留的数据源底层能力。
- 媒体名称识别、识别预览和人工纠正。
- 重命名、刮削、复制或移动及整理历史。
- 失败记录和重试。

这些元数据能力只服务于识别、整理和媒体库管理。热门推荐、探索、榜单和人物发现不属于兼容范围。

各外部元数据源可能发生接口变化，只有当前 Lite 版本测试过的请求链路属于支持范围。

## 13. 媒体服务器兼容

| 对象 | 目标等级 | 验收方式 |
|---|---|---|
| Emby | 支持 | 自动化模拟测试，配置时完成真实 Canary |
| Jellyfin | 支持 | 自动化模拟测试，配置时完成真实 Canary |
| Plex | 支持 | 自动化模拟测试，配置时完成真实 Canary |

目标保持相同官方版本的媒体库刷新、同步、查询和相关交互语义。实际发布验收至少覆盖当前 Canary 配置使用的媒体服务器，其余服务器保留自动化契约测试。

未配置媒体服务器不得创建周期性查询或刷新任务。

## 14. 前后端兼容

唯一正式支持的组合是同一 Lite 版本记录中明确配对的后端和前端。

| 组合 | 等级 |
|---|---|
| Lite 后端 + 配对 Lite 前端 | 支持目标 |
| Lite 后端 + 其他 Lite 前端版本 | 不支持，除非发布矩阵明确列出 |
| Lite 后端 + 官方前端 | 不支持 |
| 官方后端 + Lite 前端 | 不支持 |

- 前后端必须使用同一能力配置版本。
- 能力配置版本不一致时必须明确报错，不能只表现为菜单缺失或接口404。
- 插件独立页面继续使用官方插件页面机制，但受插件兼容等级和前端依赖约束。

## 15. 部署平台兼容

| 平台 | 目标等级 |
|---|---|
| Docker `linux/amd64` | 支持 |
| Docker `linux/arm64` | 支持 |
| Windows 原生安装 | 不支持 |
| 群晖 SPK | 不支持 |
| 本地 CLI 安装包 | 不支持 |

正式支持只针对项目提供并记录摘要的固定 Docker 镜像。自行修改基础镜像、依赖或挂载结构后的运行结果不属于正式兼容合同。

## 16. 兼容性验证证据

任何对象从“未验证”升级为“有条件支持”或“支持”时，至少需要记录：

- 被测对象及完整版本。
- Lite 后端和前端提交。
- 测试环境和平台。
- 相关配置条件。
- 自动化测试结果。
- 真实 Canary 结果或无法执行真实测试的原因。
- 已知限制。
- 回退方式。

兼容性结论不得跨版本自动继承。上游 MoviePilot、插件、Python依赖、Node依赖或外部 API 任一发生相关变化时，应重新评估对应矩阵项。

## 17. 文档维护规则

- 每个 Lite 正式版本发布前更新当前版本矩阵。
- 新增或移除能力时同步更新 `PROJECT_BRIEF.md`、`docs/ARCHITECTURE.md` 和本文件。
- 上游同步导致兼容等级变化时，在同步 PR 和发布说明中明确列出。
- 不把“尚未发现问题”写成“完全兼容”。
- 不隐藏不支持项，也不通过空壳接口制造兼容假象。
