## Why

MoviePilot 当前在 API、启动生命周期和模块扫描阶段会直接导入完整功能集合，缺少一个可在导入前使用的 Lite 能力真相源。若直接在各入口零散裁剪，会形成多份清单，并增加漏载非目标模块及后续合并上游更新的风险，因此需要先建立固定、不可由运行配置改写且可自动验证的能力配置基础。

## What Changes

- 新增 MoviePilot Lite 的稳定能力标识体系，覆盖保留能力和明确移除能力。
- 新增唯一、不可变的 `LITE_CAPABILITIES` 启用集合；禁用集合由全部能力减去启用集合计算。
- 新增固定的配置名称、配置版本以及确定性、可序列化的能力清单，供后续后端门控、前端构建和 Docker 依赖裁剪共同消费。
- 新增能力配置的隔离性、完整性、不可变性和序列化契约测试。
- 本变更不接入 API、模块、后台服务或前端门控，不删除依赖，也不改变当前 MoviePilot 的运行行为。
- 本变更不提供完整版与 Lite 版切换开关，禁用能力不能通过环境变量或用户设置重新启用。

## Capabilities

### New Capabilities

- `lite-capability-profile`: 定义 MoviePilot Lite 的固定能力分类、启用集合、禁用集合和机器可读清单契约。

### Modified Capabilities

无。

## Impact

- 后端：预计新增独立的 `app/core/capability.py` 及对应单元测试；该模块不得依赖业务模块、数据库、插件或外部服务。
- 前端：本变更不修改前端仓库；后续变更将消费同一能力清单并实施构建期裁剪。
- 插件：本变更不改变插件加载行为；能力清单为后续插件兼容性检查提供基础。
- API 与运行时：不新增 HTTP 路由，不修改启动生命周期、模块扫描、定时任务或消息命令。
- 依赖、数据库与配置：不调整 Python/Node/Docker 依赖，不产生数据库迁移，不修改 `/config`，不新增环境变量。
- 资源占用：本变更本身不承诺资源下降；后续门控和依赖裁剪变更以该配置为依据完成资源目标。
- 安全与隐私：能力清单不包含凭据或部署配置；普通测试不访问真实 115 或其他生产外部服务。
- 兼容与回退：属于纯增量基础设施，删除新增模块及测试即可回退；上游同步时应优先保持该文件独立，减少冲突面。
