## Context

前端当前使用 Vue Router 的静态路由数组、`i18n-menu.ts` 的主导航集合、应用中心和权限过滤器。权限过滤只能决定用户是否看见或进入项目，不能阻止组件动态导入，也不能从 Vite 产物删除禁用页面。PWA、Service Worker 预缓存和模块联邦还存在独立入口，必须与同一 capability profile 对齐。

后端 `app/core/capability.py` 已经定义稳定的 `Capability`、配置版本 2 和可序列化 `get_lite_capability_manifest()`。现有 `/api/v1/system/global` 是登录前初始化接口，只返回非敏感设置和版本信息，适合增加配对字段；它不能取代构建期裁剪，也不能成为绕过后端 API 门控的安全边界。

## Goals / Non-Goals

**Goals:**

- 让前端路由、菜单、PWA、Service Worker 和构建入口使用后端生成的唯一能力清单。
- 禁用页面在构建期不进入最终 bundle，在运行期也不能通过历史 URL、搜索入口、快捷方式或默认重定向访问。
- 保持官方登录、网盘、元数据、整理、插件、消息通知、媒体服务器和必要设置交互及权限语义。
- 保留插件动态页面机制，清晰区分核心 bundle 与手动安装插件代码。
- 为能力版本不匹配、缺少 manifest、未知 capability 和插件不可用提供失败关闭行为。
- 保留官方文件结构，控制上游同步冲突，并以测试证明依赖删除不是按体积猜测。

**Non-Goals:**

- 不重新设计 MoviePilot 的视觉语言、整体布局或基础交互。
- 不在本变更中构建、发布或部署 Docker 镜像。
- 不恢复后端已移除的 API、服务、依赖或权限模型。
- 不物理删除官方页面源码；只有最终前端构建和运行入口裁剪。
- 不把 P115StrmHelper 或其他插件页面编译进核心 bundle。
- 不因前端裁剪而删除数据库、历史配置或官方回退所需的数据。

## Decisions

### 1. 后端 manifest 是唯一事实来源

前端构建输入使用后端 `get_lite_capability_manifest()` 的序列化结果，至少包含 `profile`、`version`、排序后的 `enabled` 和 `disabled`。前端不得在 TypeScript、路由或菜单文件中再维护 Lite 启用列表。独立前端开发若缺少生成 manifest，生产构建必须失败；测试可以使用明确标注的 fixture。

### 2. 构建期裁剪与运行期校验分离

构建阶段将 manifest 转换成静态能力常量，生成只包含启用路由和页面入口的 route/menu registry；Vite 最终产物检查必须证明禁用页面及其专属动态 chunk 不存在。运行阶段再读取 `/api/v1/system/global` 的 profile/version，与构建清单比较；缺失或不匹配时显示明确错误并停止加载业务页面。运行时检查是版本保护，不以动态隐藏菜单替代构建裁剪。

### 3. 路由、菜单、PWA 使用同一注册表

路由定义保留官方相对顺序和 `meta` 权限字段，但每项增加稳定 capability 标识。菜单、应用中心、全局搜索、首页重定向、PWA 快捷方式和 Service Worker 预缓存从同一份已筛选注册表生成，禁止维护平行删除清单。未启用路径应落到明确的 404/能力不可用状态，不得误报为权限不足。

### 4. 插件采用后端确认后的延迟远程加载

核心只保留模块联邦运行时、插件导航壳和错误状态。插件页面在加载前使用后端已安装/启用/兼容结果；P115StrmHelper 缺失时核心仍可启动，并显示需要手动安装的具体提示。远程插件组件不进入核心静态扫描和预缓存范围。

### 5. 依赖删除以使用点和构建证据为准

对 `package.json` 中疑似专属依赖建立使用点矩阵。只有确认没有保留页面、共享组件、测试、构建工具或插件联邦使用时才从生产依赖移除；开发测试依赖是否保留必须单独说明。构建前后用依赖图、产物清单和运行测试证明删除没有误伤保留能力。

### 6. 后端只增加非敏感配对字段

现有 `/system/global` 响应增加 profile/version 或等价结构，不返回 enabled/disabled 之外的秘密、Token、用户配置或能力可变开关。后端 API 路由和权限门控继续独立生效；前端不能用 manifest 重新开启禁用 API。

## Risks / Trade-offs

- **上游新增页面漏归类**：将路由、菜单、PWA 和入口文件加入同步审查清单，未知页面默认不进入 Lite 构建。
- **动态导入仍被打包**：使用构建产物断言和 chunk 路径检查，而非只测试运行时菜单数量。
- **能力版本不匹配导致白屏**：提供可见的配对错误状态和固定后端/前端提交记录，失败时不加载业务路由。
- **依赖误删影响保留功能**：删除前做静态引用、模块联邦和构建测试，保留不确定依赖并记录后续候选。
- **插件页面被误判为核心**：将插件远程 URL、联邦入口和 P115StrmHelper 手动安装流程纳入独立测试，不把插件代码复制到核心产物。
- **前端与 Docker 交付脱节**：本变更只产出可追溯的 Lite 前端构建合同，Docker 固定消费和双架构候选另设审批步骤。

## Migration Plan

1. 在前端仓库完成路由、菜单、PWA、模块联邦和依赖使用点审计，锁定与后端 profile version 2 的映射。
2. 实现构建 manifest 输入、路由注册表、运行时配对检查和禁用入口失败关闭。
3. 运行类型检查、单元测试和生产构建，检查禁用页面/chunk/专属依赖不进入产物。
4. 记录 Lite 前端提交和生成 manifest 摘要；在 Docker 集成变更中固定消费该产物。
5. 首次候选仍需在配对后端上验证登录、网盘、整理、插件、消息和媒体服务器流程；失败时回退到上一个固定前端提交。

## Open Questions

无。构建 manifest 的具体文件生成位置可在实现时按现有 Vite 结构选择，但不得改变唯一事实来源、失败关闭和产物检查三项合同。
